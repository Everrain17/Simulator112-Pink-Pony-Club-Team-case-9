# System112

**System112** — учебно-симуляционная система для подготовки и оценки работы оператора системы **112**.

Система позволяет моделировать работу оператора с входящими вызовами, обрабатывать обращения, заполнять карточку происшествия и получать автоматическую оценку действий обучаемого.

Проект состоит из серверной части, симуляционного ядра, AI-компонентов, интерфейсов обучаемого и преподавателя, а также инструментов для настройки, сборки и отладки.

## Основные приложения

### `System112.exe`

Основное приложение системы для администратора.

Запускает необходимые компоненты системы:

* Qwen;
* TTS Server;
* C# Backend;
* Admin Tool.

**Важно:** `System112.exe` должен запускаться из корня проекта `Simulator112`, поскольку он использует расположение остальных компонентов относительно корня проекта.

### `System112_Student.exe`

Приложение обучаемого.

Может запускаться из любого места на компьютере обучаемого.

### `System112_Teacher.exe`

Приложение преподавателя.

Может запускаться из любого места на компьютере преподавателя.

# 2. Требования к серверному компьютеру

На серверном компьютере должны быть установлены:

* **Windows**;
* **Docker Desktop**;
* **Python 3.11**;
* **Visual Studio** с поддержкой C# и установленным **.NET SDK**.

Для Visual Studio необходимо установить workload:

```text
ASP.NET and web development
```

Он используется для работы и запуска C# Backend.

### Python

Python необходим для:

* Python Backend;
* Admin Tool;
* других Python-компонентов системы.

При первоначальной настройке `setup.bat` пытается автоматически установить необходимую версию Python и подготовить виртуальное окружение.

Если автоматическая установка Python не удалась, Python необходимо установить вручную, после чего повторно запустить `setup.bat`.

### Docker Desktop

Docker Desktop используется для запуска:

* PostgreSQL;
* Redis.

Docker Desktop должен быть установлен и запущен на серверном компьютере.

### Клиентские компьютеры

На компьютеры обучаемых и преподавателя не требуется устанавливать Docker, Python или Visual Studio, если используются готовые:

```text
System112_Student.exe
System112_Teacher.exe
```

# 5. Настройка серверного компьютера

## Шаг 1. Подготовить проект

Распакуйте проект таким образом, чтобы его корнем была папка:

```text
Simulator112
```

Важно сохранить исходную структуру каталогов.

---

## Шаг 2. Установить необходимые программы

Перед первым запуском сервера установите:

1. Docker Desktop.
2. Python 3.11.
3. Visual Studio.
4. В Visual Studio workload:

```text
ASP.NET and web development
```

Убедитесь, что вместе с Visual Studio установлен **.NET SDK**.

Если Python устанавливается автоматически через `setup.bat`, этот шаг можно пропустить.

---

## Шаг 3. Запустить `setup.bat`

В корне проекта находится:

```text
setup.bat
```

Запустите его.

Скрипт выполняет первоначальную настройку серверной части:

* проверяет виртуальное окружение Python;
* проверяет необходимые зависимости;
* при необходимости устанавливает Python;
* устанавливает Python-зависимости;
* проверяет Docker;
* запускает PostgreSQL;
* запускает Redis;
* ожидает готовности PostgreSQL;
* выполняет миграции базы данных.

Если автоматическая установка Python завершается ошибкой, установите **Python 3.11 вручную**, после чего повторно запустите `setup.bat`.

После успешного выполнения серверная часть готова к работе.

---

# 6. Настройка Windows Firewall

После выполнения `setup.bat` необходимо настроить доступ к системе по локальной сети.

Для этого используется:

```text
tools/firewall/firewall.bat
```

Скопируйте `firewall.bat` в корень проекта `Simulator112`.

После этого:

**Правая кнопка мыши → Запуск от имени администратора**

Скрипт открывает необходимые входящие TCP-порты:

```text
5000 — C# Backend
8010 — Python Backend
8000 — TTS Server
```

После выполнения скрипта другие компьютеры в локальной сети смогут подключаться к серверу.

---

# 10. Работа с вызовами

Во время работы системы обучаемый получает входящий вызов.

В процессе обработки вызова система сохраняет связанные данные, включая:

* данные вызова;
* карточку оператора;
* Ground Truth;
* диалог;
* анализ;
* нарушения;
* результат оценки.

После завершения вызова данные сохраняются для дальнейшего просмотра преподавателем.

---

# 11. История и данные преподавателя

Преподаватель может просматривать сохранённые вызовы обучаемых.

Для каждого вызова могут быть доступны:

* обучаемый;
* информация о вызове;
* карточка оператора;
* Ground Truth;
* нарушения;
* оценка классификации;
* выбранные и необходимые службы;
* необходимые признаки;
* диалог;
* анализ.

История сохраняется на сервере и не должна зависеть от текущего состояния запущенного вызова.

# 12. Экспорт данных

В интерфейсе преподавателя доступна функция:

**«Выгрузить данные»**

При экспорте выбирается папка, после чего система создаёт:

```text
System112_Data/
└── Export_<timestamp>/
    ├── all_data.json
    ├── current_user.json
    ├── runtime_state.json
    ├── classifier.json
    ├── students.json
    ├── saved_calls.json
    └── manifest.json
```

Экспорт предназначен для сохранения и передачи результатов работы системы.

# 13. Инструменты разработки

В папке:

```text
tools/
```

находятся вспомогательные инструменты проекта.

### `tools/build`

Файлы для самостоятельной сборки `.exe`.

Если требуется повторно собрать приложения, содержимое этой папки необходимо временно скопировать в корень `Simulator112`, после чего использовать соответствующий BAT-файл.

### `tools/debug`

Инструменты для ручного запуска и остановки компонентов системы во время разработки и отладки.

`admin-start.bat` запускает компоненты системы вручную.

В самом файле указано, какой компонент, из какой директории и каким способом запускается.

`stop.bat` используется для остановки запущенных процессов.

### `tools/docker_setup`

Содержит `setup.bat` для первоначальной настройки серверного окружения.

### `tools/firewall`

Содержит `firewall.bat` для настройки Windows Firewall.

Более подробная информация находится в README соответствующих папок.

# 17. Основные порты

| Компонент      |   Порт |
| -------------- | -----: |
| Python Backend | `8010` |
| C# Backend     | `5000` |
| TTS Server     | `8000` |
| Qwen           | `8080` |
| PostgreSQL     | `5433` |
| Redis          | `6379` |

Порты `5000`, `8010` и `8000` открываются для входящих подключений скриптом `firewall.bat`.

PostgreSQL и Redis используются серверными компонентами и не требуют установки на клиентские компьютеры.
